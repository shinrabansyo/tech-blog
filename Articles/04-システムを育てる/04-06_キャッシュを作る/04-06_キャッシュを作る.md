# I-cacheとD-cacheを作って、メモリ待ち時間を隠そう

> タグ: CPU自作 / キャッシュ / I-cache / D-cache / cache line / FPGA

CPUが高速でも、命令やデータを読むたびに遅いメモリを待つと、実行時間の多くが待機になります。最近使った周辺の内容を小さく速いメモリへ置く仕組みがキャッシュです。

森羅万象CPUでは2025年11月にI-cacheの簡易実装をテストし、2026年1月にCPUへ統合しました。2026年2月にはD-cacheのテストを通し、両者のインターフェースをそろえました。

## cache line単位で持ってくる

1 byteだけ要求されても、その周辺を続けて使うことがよくあります。キャッシュは複数byteをcache lineとしてまとめて読みます。

2026年2月時点の構成は次です。

| 項目 | I-cache | D-cache |
| --- | ---: | ---: |
| 容量 | 4096 byte | 4096 byte |
| line size | 32 byte | 32 byte |
| way数 | 1 | 2 |
| set数 | 128 | 64 |

I-cacheの1 wayはdirect mappedです。D-cacheは2 way set associativeで、同じsetに2本のlineを置けます。

## アドレスを3つに分ける

32 bitアドレスは、cache line内の位置、set番号、tagに分けて使います。

```text
┌──────── tag ────────┬── set ──┬ offset ┐
31                                      0
```

32 byte lineではoffsetが5 bitです。I-cacheは128 setなのでsetが7 bit、残りがtagです。D-cacheは64 setなのでsetが6 bitです。

読みたいアドレスのsetを選び、保存されているtagが一致し、validであればhitです。一致しなければmissとして下位メモリから32 byteを補充します。

## hitとmiss

```text
hit:
  cache内のlineから必要部分を返す

miss:
  memoryへline readを要求
  32 byteをcacheへ格納
  要求された部分を返す
```

missの間はCPUを待たせます。要求を受理したか、lineの何beat目まで届いたか、応答を返したかを状態として持ちます。

最初のアクセスはmissでも、次の命令や隣のデータは同じlineに含まれ、hitしやすくなります。これは空間的局所性を利用しています。

## 48 bit命令はline境界をまたぐ

森羅万象CPUの命令は6 byteです。32 byte lineのoffset 30から命令を読むと、最初の2 byteは現在のline、残り4 byteは次のlineにあります。

```text
line A: ... [byte 30][byte 31]
line B: [byte 0][byte 1][byte 2][byte 3] ...
         └──── 6 byte instruction ────┘
```

命令長6 byteは32の約数ではないため、この状況は定期的に起こります。2026年1月に2 lineにまたがるfetchへ対応し、2回のcache access結果を結合しました。

## D-cacheでは書き込みもある

D-cacheはloadだけでなくstoreを扱います。byte、half word、wordのwrite maskと、line境界をまたぐaccessを考えます。

書き込み方式には、cacheと下位メモリを同時に更新するwrite-throughや、cacheだけ更新して追い出すときに下位メモリへ書くwrite-backがあります。どちらを採るかでdirty bitや応答タイミングが変わります。

この記事では一般的な方式の名前までを紹介し、森羅万象CPUの完成仕様として方式を断定しません。実装を説明する際は、対象commitのD-cache state machineとtestを確認します。

## 命令を書き換えた後

ブートローダーの `isb` は命令メモリへ書きます。I-cacheに同じアドレスの古いlineが残ると、書き換え後も古い命令を実行する可能性があります。

2026年2月にはI-cache側のwrite portを整え、pipeline版でも `isb` を扱う修正が入りました。命令書き込み、cache更新または無効化、再fetchの順序をそろえる必要があります。

## cache test

- cold startの最初のaccessがmissになる
- 同じlineへの2回目のaccessがhitになる
- 同じsetでtagが違う場合を区別する
- 2 wayの両方を使える
- line境界をまたぐ48 bit fetchを結合できる
- D-cacheでbyte maskと境界accessを扱える
- resetまたはinvalidate後に古いlineをhitにしない
- `isb` 後に新しい命令をfetchする

hit/miss、要求address、選択set、tag、状態、下位メモリ要求を波形へ並べます。

## 今回の到達点

4 KiBのI-cacheとD-cacheを加え、32 byte lineから命令とデータを供給する構成になりました。48 bit命令固有のlineまたぎも処理します。

# フレームバッファを作って、画面へ色を出そう

> タグ: CPU自作 / 映像出力 / フレームバッファ / パレット / FPGA

UARTは文字を順番に送るのが得意です。画像や自由な位置の文字を表示するには、画面上の各点に対応するメモリを用意すると扱いやすくなります。このメモリをフレームバッファと呼びます。

森羅万象CPUでは2025年春に映像出力を統合し、色、拡大率、表示位置を調整しました。ここでは物理的な映像端子の細部より、CPUから画素が表示されるまでの考え方を扱います。

## 画面は左上から走査される

映像出力回路は、表示規格に合わせて横方向と縦方向の位置を数えます。現在位置が表示領域の内側なら画素の色を出し、外側なら同期やblank期間として扱います。

```text
(0,0) → (1,0) → (2,0) → ... → 次の行
  ↓
(0,1) → (1,1) → ...
```

このカウンタはCPUよりずっと規則的に進みます。CPUが画面を更新していない間も、映像回路は同じフレームバッファを繰り返し読みます。

> **画像差し込み候補**  
> `images/video-scan.png`：横走査、行末、次の行、blank期間を示す自作図。映像規格の既存図を転載しない。

## 論理画面は128×128

ISA v1期の森羅万象CPUでは、論理的な画面を128×128 pixel、16色としました。1 pixelは4 bitなので、1 byteに2 pixelを詰められます。

```text
1 byte
┌────────┬────────┐
│ pixel A 4 bit │ pixel B 4 bit │
└────────┴────────┘
```

1行は `128 / 2 = 64 byte`、画面全体は `64 × 128 = 8192 byte` です。32 bitのCPUなら1回の書き込みで最大8 pixelぶんを更新できますが、先頭位置やbyte maskを正しく扱う必要があります。

## 色番号とパレットを分ける

フレームバッファへRGBの全bitを置く代わりに、0～15の色番号を置きます。実際のRGB値は16個のパレットから選びます。

```text
framebufferの4 bit値 ──> palette[色番号] ──> 24 bit RGB
```

同じ画像データのままパレットだけを書き換えて、配色を変えられます。CPUからは映像モード用のデバイスID 6、パレット用のID 7を使う構成が作られました。

> **画像差し込み候補**  
> `images/palette-example.png`：4 bitの色番号と16個のRGB色、それを使った小さな画像を並べた自作図。

## 座標からアドレスを求める

横座標を `x`、縦座標を `y` とすると、対象byteの位置は次の考え方で求められます。

```text
byte offset = y × 64 + x / 2
```

`x` が偶数か奇数かで、byteの上位4 bitと下位4 bitのどちらを使うかを選びます。森羅万象CPUのv1メモリマップでは、フレームバッファ領域を `0x01000000` 付近へ置きました。

この計算はソフトウェアで行えますが、映像回路も同じ配置で読む必要があります。片方だけ上下のnibbleを逆にすると、隣り合う2 pixelが入れ替わります。

## 拡大して中央へ置く

物理的な出力解像度より128×128は小さいため、1個の論理pixelを複数の物理pixelへ広げます。

```text
logical x = (physical x - left margin) / scale
logical y = (physical y - top margin)  / scale
```

開発では拡大率と表示位置を調整し、画面の中央へ置きました。割り算回路をそのまま置くより、scaleが2の累乗ならbit shiftを使うなど、合成される回路も考えます。

## CPUと映像回路が同じメモリを使う

CPUはフレームバッファへ書き、映像回路は継続して読みます。1個のメモリに2つの利用者がいるため、dual-port memoryを使うか、アクセスを仲裁します。

同時アクセスで確認する点は次です。

- CPUが書いている間も映像読み出しが期限に間に合う
- 同じアドレスを同時に読み書きしたときの値
- reset直後の未初期化画素
- フレームバッファ外への書き込みをどう扱うか

画面更新中に新旧のフレームが混ざるtearingも起こり得ます。初期段階では許容し、必要になったら垂直blank期間に更新する方法やdouble bufferingを検討します。

## 最初は色の縞から

いきなり文字表示を作らず、次の順で試すと切り分けやすくなります。

1. 映像回路だけで固定色を出す
2. 座標から作った色の縞を出す
3. 固定内容のフレームバッファを読む
4. CPUから1 pixelを書き換える
5. 四角形や文字をソフトウェアで描く

> **画像差し込み候補**  
> `images/video-color-test.jpg`：実機で固定色、縞、128×128画像を順に表示した写真。自分たちのボードと画面を撮影する。

## 今回の到達点

CPUがメモリへ4 bitの色番号を書き、映像回路が16色のRGBへ変換して画面へ出せるようになりました。入出力装置が増えたことで、CPUは計算回路から小さなコンピュータへ近づきます。

Verylへの移植経緯は、追加記事「01-10 ChiselからVerylへ」で扱っています。次はSPIを使い、SDカードから512 byteのblockを読みます。

### 仕様について

128×128、4 bit/pixel、16色パレット、フレームバッファの配置は森羅万象CPUのISA v1期の構成です。物理出力の解像度やタイミングは、対象ボードのTop設定と映像規格を確認してください。

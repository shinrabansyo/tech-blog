# 自作コンパイラで、高級言語からCPUを動かそう

> タグ: CPU自作 / コンパイラ / 字句解析 / 構文解析 / レジスタ割り当て / ABI

アセンブリ言語ならCPUの全命令を直接使えますが、処理が長くなるほどレジスタや分岐ラベルの管理が難しくなります。高級言語から機械語を作るコンパイラがあれば、条件分岐、loop、関数をより大きな単位で書けます。

森羅万象CPUでは2024年春に字句解析と四則演算の構文解析を始め、2025年夏にHello WorldとFizzBuzzを動かしました。その後、乗除算の変換、レジスタ割り当て、生存区間の問題を修正し、2026年2月にはライブラリ整備へ進みました。

## コンパイラの出口を先に決める

コンパイラは、CPUが実行できる命令を出さなければなりません。そのため、入口の言語だけでなく、次を先に確認します。

- ISAにある算術・比較・分岐命令
- load/storeで扱える幅
- 関数呼び出しのABI
- 使用できるレジスタ
- アセンブラが受け付ける書式
- 実行ファイルSELFの配置

コンパイラが直接48 bitの機械語を出す方法もありますが、まずアセンブリを出力すると人が途中結果を読めます。アセンブラ単体のテストも再利用できます。

```text
source
  ↓ compiler
assembly
  ↓ assembler
machine code / SELF
  ↓ bootloader
CPU
```

## 字句解析

字句解析器（lexer）は文字列をtokenへ分けます。たとえば識別子、数値、演算子、括弧、区切り記号を区別します。

```text
total = a + 10

identifier(total)
assign
identifier(a)
plus
integer(10)
```

ここではまだ「足し算の左右に正しい式があるか」までは判断しません。文字の並びを、次の段階が扱いやすい部品へ変えます。

## 構文解析

構文解析器（parser）はtoken列から式や文の構造を作ります。`1 + 2 * 3` なら、掛け算を先に行う優先順位を木で表せます。

```text
      +
     / \
    1   *
       / \
      2   3
```

括弧、単項minus、比較、条件分岐が増えると規則も増えます。最初は整数の四則演算だけを通し、1機能ずつ構文木とエラー位置を確認します。

## 構文木から命令列へ

式の各部分を計算し、結果をレジスタまたは一時的なスタック領域へ置きます。条件分岐では、真の場合、偽の場合、合流地点のラベルを作ります。

```text
if condition:
    then block
else:
    else block

  ↓

conditionを計算
偽なら else_label へ分岐
then block
end_label へ分岐
else_label:
else block
end_label:
```

FizzBuzzは、loop、剰余に相当する計算、複数の条件、文字出力をまとめて確認できる題材です。2025年7月にHello WorldとFizzBuzzが動いたことで、個別の式からプログラム全体へ進みました。

## 乗算と除算

ハードウェア命令の有無や速さに応じて、演算を別の命令列へ置き換えます。2の累乗による乗算は左shiftへ、条件が合う符号なし除算は右shiftへ変換できます。

ただし、負数の除算は単純な算術右shiftと同じ結果にならない場合があります。開発では2025年秋に負数を含む除算結果をC言語の整数除算の意味へ合わせました。最適化は、入力範囲と丸め方向を保つと証明できる場合だけ適用します。

## レジスタ割り当て

計算途中の値は、いつまでもすべてのレジスタへ置けません。各値が最後に使われるまでの区間を生存区間と呼び、重ならない値へ同じレジスタを割り当てます。

```text
value A: [作成────────最後の利用]
value B:          [作成────利用]
value C:                         [作成─利用]
```

AとBは同時に必要なので別レジスタ、Aの終了後に作るCは同じレジスタを再利用できます。足りなければ一部をスタックへ退避します。

2025年秋から2026年2月に、loopをまたぐ生存区間や複数loopがある場合の不具合を修正しました。一直線の式だけで成功しても、制御フローが分かれると「後で使う値」の判定が変わります。

## ABIにつなぐ

関数呼び出しでは02-04で決めた規約を使います。

- 引数と戻り値を `r10`～`r19` へ置く
- 必要な戻り先とレジスタを保存する
- stack pointerとframe pointerを正しく動かす
- callee-saved registerを元へ戻す

コンパイラ、手書きアセンブリ、ライブラリが同じABIへ従えば、別々に作った関数を組み合わせられます。

## 正しさを段階的に比べる

コンパイラの不具合かCPUの不具合かを分けるため、複数の地点で結果を確認します。

1. token列が期待どおりか
2. 構文木が演算の優先順位を表すか
3. 出力assemblyを人が追えるか
4. emulatorまたはCPU simulationで結果が合うか
5. FPGA実機でも同じ出力になるか

小さな式、条件分岐、単一loop、入れ子loop、関数呼び出しの順に増やします。期待値は、既存処理系で動かした結果とも比較します。

## 今回の到達点

字句解析と構文解析から始め、Hello WorldとFizzBuzzを実行し、より複雑なloopへ対応するレジスタ割り当てを整えました。次の段階は、文字列、メモリ確保、入出力を共通関数として使える標準ライブラリです。

その前に、外部メモリを効率よく使うキャッシュをCPUへ追加します。

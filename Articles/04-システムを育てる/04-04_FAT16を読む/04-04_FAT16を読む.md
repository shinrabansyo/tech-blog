# FAT16を読んで、ファイル名からデータを探そう

> タグ: CPU自作 / FAT16 / ファイルシステム / SDカード / LFN

SDカードのblockを直接読めるようになっても、「プログラムは何番blockにあるか」を毎回手で決めるのは不便です。ファイルシステムを読めれば、名前とパスを使ってファイルを探せます。

森羅万象CPUでは2025年夏から秋にFAT16の読み出しを作り、短いファイル名、長いファイル名、絶対パスでの `cat` と `ls`、複数clusterにまたがる読み出しを試しました。この記事で扱う到達点は読み出しです。ファイル書き込みとFAT32は当時の検討項目であり、完成済みとはしません。

## blockとcluster

SDカードは512 byteのblockとして読めます。一方、FAT16は複数sectorをまとめたclusterを、ファイルへ割り当てる単位として使います。

```text
SD block/sector → 512 byte
cluster         → 1個以上のsector
file            → 1個以上のcluster
```

ファイルが大きいと、次のcluster番号をFAT（File Allocation Table）からたどります。

## 最初のsectorから配置を計算する

FAT volumeの先頭にはBPB（BIOS Parameter Block）を含むboot sectorがあります。ここから主に次の値を読みます。

- 1 sectorあたりのbyte数
- 1 clusterあたりのsector数
- reserved sector数
- FATの個数
- 1個のFATが使うsector数
- root directory entry数
- volume全体のsector数

これらを使って、FAT、root directory、data領域の先頭を計算します。構造体をそのままcastするとalignmentやエンディアンに依存するため、byte offsetを確認してlittle endianで組み立てます。

## directory entryを読む

通常のFAT directory entryは32 byteです。短いファイル名（SFN）は、基本名8文字と拡張子3文字の8.3形式で入ります。

```text
EXAMPLE TXT
12345678 123
```

entryには属性、先頭cluster、file sizeなどもあります。未使用entry、削除済みentry、volume label、directoryを区別し、探している名前と比較します。

## 長いファイル名

LFN（Long File Name）は、通常entryの直前に複数の専用entryとして置かれます。名前が長い場合は断片を集め、順番を直して1つの名前へ戻します。

実装時に気を付ける点は次です。

- LFN entryの順番
- 1つの名前が複数entryにまたがる場合
- 終端とpadding
- 対応するSFN entryとの関係
- 文字コードの扱い

最初はASCII範囲の名前で構造を確認し、その後に扱える文字範囲を明文化します。「日本語ファイル名を完全に扱える」とは、文字変換と比較方法まで検証してから記載します。

## パスを1要素ずつたどる

`/dir/sub/file.txt` を探す場合、文字列全体を一度に検索するのではなく、`dir`、`sub`、`file.txt` に分けます。

1. root directoryから `dir` を探す
2. `dir` の先頭clusterへ移る
3. そのdirectoryから `sub` を探す
4. `sub` の中から `file.txt` を探す
5. fileの先頭clusterとsizeを得る

開発では絶対パスを使う `ls` と `cat` を作りました。`ls` はdirectory entryを列挙し、`cat` はfile dataを読み出します。

## cluster chainをたどる

ファイルが1 clusterに収まらないときは、FAT entryから次のclusterを取得します。

```text
cluster 5 → FAT[5] = 9
cluster 9 → FAT[9] = 10
cluster 10 → end of chain
```

最後のclusterにはfile sizeより余分なbyteが含まれることがあります。chainの終端だけでなくdirectory entryのfile sizeを使って、必要なbyte数で止めます。

壊れた媒体を考えるなら、範囲外cluster、予約値、bad cluster、循環するchainも検出します。教材の最小実装でも、たどる回数に上限を設けると無限loopを避けられます。

## 1段ずつテストする

FAT16は計算箇所が多いため、次の順に結果をUARTへ出します。

1. BPBの値
2. 計算した各領域の先頭sector
3. root directoryのSFN
4. LFNを復元した名前
5. 1階層のfile
6. 複数階層の絶対パス
7. 複数clusterにまたがるfile

PC側でも同じSDイメージを解析し、期待するsector番号やbyte列と比較します。

## 当時まだ完了扱いにしない内容

開発履歴にはFATへの書き込みやFAT32への拡張案がありますが、2026年3月より前の完成項目として確認できるのはFAT16の読み出し側です。書き込みでは、dataだけでなくFATの複製、directory entry、空きclusterの管理、失敗途中の整合性まで必要になります。

GPT（GUID Partition Table）を読んでpartitionを探す案も整理されましたが、同期間に完成したブート経路としては扱いません。

## 今回の到達点

FAT16の構造を読み、ファイル名と絶対パスから目的のデータへ到達できるようになりました。複数clusterをたどれるため、1 clusterより大きいSELFや画像も扱う土台になります。

次は、人が読みやすい高級言語を森羅万象CPUの命令へ変換する自作コンパイラを扱います。

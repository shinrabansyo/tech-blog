# SELF形式とブートローダーで、SDカード上のプログラムを起動しよう

> タグ: CPU自作 / ブートローダー / 実行形式 / SELF / 命令メモリ

SDカードから512 byteを読めても、それが命令なのかデータなのか、どこへ置くのかは分かりません。実行ファイルの先頭へ配置情報を付け、ブートローダーが読み取れるようにします。

森羅万象CPUでは2025年6月から7月に、命令メモリへ書く `isb` 命令、SELF実行形式、ブートローダーを作り、読み込んだプログラムの実行を確認しました。

## 起動時の難しさ

森羅万象CPUは命令メモリとデータメモリを分けています。普段のload/storeはデータメモリを扱うため、SDカードから読んだbyteを命令メモリへ置けません。

```text
SDカード → SPI → データメモリ
                         │
                         └─ ここから命令メモリへ移したい
```

そこで命令メモリへ書くための `isb` を追加しました。この `isb` は森羅万象CPU固有の命令です。他のアーキテクチャで同じ名前が別の意味を持つ場合があります。

## SELFヘッダ

SELFはこのプロジェクト用の単純な実行形式です。先頭16 byteに次の情報を置きます。

| offset | size | 内容 |
| ---: | ---: | --- |
| 0 | 4 byte | magic `SELF` |
| 4 | 4 byte | format version |
| 8 | 4 byte | data領域のsize |
| 12 | 4 byte | instruction領域のsize |

ファイル内ではヘッダに続いてデータと命令を置きます。リトルエンディアンで先頭4 byte `53 45 4c 46` を32 bitとして読むと、`0x464c4553` になります。

magicは「このファイルをSELFとして読んでよいか」を見分ける印です。偶然一致する可能性や破損検出までは解決しないため、完全な安全性を保証するものではありません。

## ブートローダーの手順

開発したローダーの流れを整理すると次のようになります。

1. SDカードのblockを作業用バッファへ読む
2. magicが `SELF` か確認する
3. versionを確認する
4. data sizeとinstruction sizeを読む
5. data領域をデータメモリへコピーする
6. instruction領域を `isb` で命令メモリへコピーする
7. エントリ位置へ分岐する

初期実装では作業用バッファを `0x400` 付近に置き、ロード後にアドレス0へ移って実行するコードを作りました。メモリ配置が重なるとローダー自身や未コピーのデータを壊すため、領域を図にして確認します。

```text
データメモリ:
  bootloaderの作業領域
  SD受信バッファ
  読み込むプログラムのdata

命令メモリ:
  bootloader
  読み込むプログラムのinstruction
```

## 6 byte命令をコピーする

森羅万象CPUの命令は48 bit、つまり6 byteです。instruction sizeがbyte数なら、6の倍数か確認し、6 byteずつ正しい順で命令メモリへ渡します。

端数、範囲外、サイズの加算overflowを確認しないローダーは、壊れたファイルによって別の領域へ書き込みます。教材の最小実装でも、少なくとも次を検査します。

- magicとversion
- data sizeとinstruction sizeがメモリ容量内か
- instruction sizeが6の倍数か
- 各領域の終端計算がoverflowしないか
- 読み込み途中でSD通信が失敗していないか

## isb後に実行する

命令メモリへの書き込み完了前に分岐してはいけません。単純なCPUでは `isb` の完了を待ってから次へ進みます。後に命令キャッシュを追加すると、書いたアドレスに古い命令が残る可能性も考える必要があります。

2026年2月には `isb` とキャッシュを組み合わせる修正も行われました。CPUの構成が変わると、ブートローダーが依存する「書いた命令がいつ見えるか」も変わります。

## エラーをUARTへ出す

ブート失敗時に無言で停止すると、原因が分かりません。各検査へ短いエラー番号を割り当てます。

```text
E1: SD read失敗
E2: magic不一致
E3: version非対応
E4: sizeがメモリ範囲外
```

UARTが使えない初期段階では、GPIOのLEDへ下位bitを出す方法もあります。成功時には読み込んだプログラム側から別の文字や画面を出し、制御が移ったことを確認します。

## 今回の到達点

SDカードから読んだbyte列を、データと命令へ分けて配置し、別のプログラムを起動できるようになりました。CPUの回路を書き換えなくても、外部の実行ファイルを交換して動作を変えられます。

次はFAT16を読み、固定block番号ではなくファイル名からSELFを見つける方法へ進みます。

### 仕様について

SELFの名前、ヘッダ、`isb` は森羅万象CPU固有です。2025年夏時点の実装を説明しており、一般的なELF形式とは互換性がありません。

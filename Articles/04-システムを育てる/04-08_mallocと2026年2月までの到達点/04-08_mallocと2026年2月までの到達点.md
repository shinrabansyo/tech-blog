# mallocとライブラリを準備し、2026年2月までを振り返ろう

> タグ: CPU自作 / malloc / free list / 標準ライブラリ / 開発記録

CPU、周辺回路、記憶装置、コンパイラがそろうと、次はアプリケーションから共通して使える機能が必要になります。文字出力、ファイル読み出し、メモリ確保を毎回一から書かず、ライブラリとして呼び出せるようにします。

森羅万象CPUの作業記録では、2026年2月に `malloc`、free list、双方向linked listを使うデモが動き、ライブラリ整備へ進みました。本記事は、ホームページ制作とISA v2へ進む前、2026年2月18日にsingle-cycle版とpipeline版の実行traceを比較したところまでを区切りとします。

## 静的な配置だけでは足りなくなる

小さなプログラムなら、使う配列の大きさとaddressを事前に決められます。しかし読み込んだfile数や入力データ量が実行時まで分からない場合、必要な量だけmemoryを確保したくなります。

`malloc` は要求されたbyte数の空き領域を探し、その先頭addressを返す関数です。使い終わった領域は `free` で返します。

```text
heap:
┌──── used ────┬──── free ────┬── used ──┬── free ──┐
               ↑
          mallocが探す
```

CPU命令として `malloc` があるわけではありません。load/store、比較、分岐、関数呼び出しを組み合わせたソフトウェアです。

## free list

空いているblockを一覧にしたものがfree listです。各blockの管理情報には、少なくとも大きさと次の空きblockへの参照が必要です。

双方向linked listなら前後への参照を持ち、途中のblockを外したり戻したりしやすくなります。

```text
null <- [free A] <-> [free B] <-> [free C] -> null
```

ただし、作業記録からmalloc内部のすべての方式までは確定できません。この記事の図はfree listを学ぶための一般的な構成です。実装固有のheader size、探索方式、alignment、隣接blockの結合方法は、公開前に対象sourceで補います。

## alignmentと範囲

32 bit値を扱うなら、返すaddressを4 byte境界へそろえるとload/storeしやすくなります。要求sizeにも管理情報とalignmentぶんの余裕が必要です。

最低限、次の失敗を扱います。

- 十分な空き領域がない
- size 0を要求した
- 計算中にsizeがoverflowした
- heap範囲外を指した
- 同じ領域を二度freeした
- listの参照が壊れた

教材として最初に実装する範囲と、壊れたpointerから守る範囲は分けて記載します。確認していない安全性を「保証する」とは書きません。

## ライブラリへまとめる

自作コンパイラから次のような関数を同じABIで呼べれば、アプリケーションを書きやすくなります。

- UARTへの文字・数値出力
- 時間やGPIOの読み出し
- SPIとSD block read
- FAT16の `ls` と `cat`
- 画面のpixel・文字描画
- `malloc` と `free`

関数名と引数だけでなく、失敗時の戻り値、壊してよいレジスタ、必要なbuffer sizeもAPIとして決めます。

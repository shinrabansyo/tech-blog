# SPIでSDカードを初期化し、1 block読んでみよう

> タグ: CPU自作 / SDカード / SPI / CMD17 / ブート

SPI回路が動いたら、SDカードへコマンドを送り、保存されたデータを読みます。SDカードは単なるSPIメモリではなく、決められた初期化手順と応答形式を持つデバイスです。

森羅万象CPUでは2024年秋からコマンドを試し、2025年5月にSDカードからの読み出しを確認しました。この記事は開発で使ったSPI modeの流れを、役割が分かる範囲に絞って説明します。

## 最初は低速で始める

電源投入直後は、CSを非選択にした状態でdummy clockを送り、カードをSPI modeへ入れる準備をします。初期化中はSPIクロックを低くし、完了後に対応範囲内で速くします。

```text
電源安定
  ↓
CSを非選択にしてdummy clock
  ↓
CSを選択して初期化コマンド
  ↓
初期化完了後にblock read
```

CSの極性や必要なクロック数は仕様を確認します。森羅万象CPUではCSをGPIOから操作し、SPI mode 0を使うコードを作りました。

## コマンドは6 byte

SPI modeのコマンドは、コマンド番号、32 bit引数、CRCを含む6 byteです。送った直後に応答が来るとは限らないため、`0xff` を送りながら有効な応答を待ちます。

開発した初期化コードでは、主に次の順で進めました。

| コマンド | 目的 |
| --- | --- |
| CMD0 | idle状態へリセットする |
| CMD8 | 電圧範囲とecho patternを確認する |
| CMD55 + ACMD41 | 初期化が終わるまで繰り返す |
| CMD58 | OCRを読み、カードの状態を確認する |
| CMD17 | 1 blockを読む |

CMD0ではCRC `0x95`、CMD8では引数 `0x000001aa` とCRC `0x87` を使いました。SPI modeではCRCが常に必須とは限りませんが、初期化時に正しい値が必要なコマンドがあります。

## 応答を待つ

カードがMISOへ `0xff` を返している間は、まだ応答が始まっていない可能性があります。無限に待つと不具合時にCPU全体が止まるため、回数または時間でtimeoutを設けます。

```text
repeat until timeout:
    received = spi_transfer(0xff)
    if received is response:
        break
```

応答のbitにはidle、illegal commandなどの状態が含まれます。「何か返った」だけで成功とせず、期待するbitを調べます。

## ACMDは2つのコマンドで送る

`ACMD41` の前には `CMD55` を送ります。カードがまだ初期化中なら、少し待って同じ組を繰り返します。

```text
CMD55
ACMD41
  ├─ idleのまま → 待って再試行
  └─ ready       → 次へ
```

クロックカウンタがあれば、試行回数だけでなく経過時間でもtimeoutを管理できます。UARTへ応答値を出すと、どのコマンドで止まったかを実機で確認できます。

## CMD17で512 byte読む

初期化後、`CMD17` でsingle block readを要求します。カードからdata tokenが来るまで待ち、その後512 byteを受け取ります。末尾にはCRCが続くため、データと混ぜないように読み進めます。

```text
CMD17
  ↓ response
  ↓ data token
  ↓ 512 byte data
  ↓ CRC 2 byte
```

カードの種類によって、引数をblock番号として扱うかbyte addressとして扱うかが変わります。CMD58などで種類を確認し、対象に合うアドレスを渡します。

## まず既知の模様を置く

ファイルシステムを同時に解析すると原因が増えます。最初はPCでSDカードの既知のblockへ識別しやすいbyte列を置き、そのblockを直接読みます。

```text
00 01 02 03 04 ...
または
53 48 49 4e 52 41 ...
```

SPI波形、受信バッファ、UARTへ出したhexを比較し、512 byteの欠落やずれがないことを確認します。

## 文字化けの原因を分ける

開発では、block read後のUART表示で文字化けを修正しました。原因を探すときは次を別々に確認します。

- SDカードから受けたbyte自体が正しいか
- メモリへ置くアドレスが1 byteずつ進むか
- UARTへ渡す順番とタイミングが正しいか
- バイナリを文字列として表示していないか

受信したbyteをhexで表示すれば、通信の破損と文字コードの解釈を分離できます。

## 今回の到達点

SDカードをSPI modeで初期化し、指定した512 byte blockを読み出せるようになりました。これだけではファイル名は分かりませんが、記憶装置からCPUのメモリへデータを運ぶ道ができました。

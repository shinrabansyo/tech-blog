# 3つの命令を動かして、小さなCPUを完成させる

> タグ: CPU自作 / Chisel / 命令セット / Fetch / Decode / レジスタ

こんにちは、森羅万象プロジェクトです。

今回は、命令メモリ、プログラムカウンタ、レジスタ、デコーダ、ALUをつなぎます。実行するプログラムは次の3命令です。

```text
addi r4 = r0, 3
addi r5 = r0, 5
add  r6 = r4, r5
```

1命令目で3を保存し、2命令目で5を保存し、3命令目で足した8を保存します。

## 最初に知っておきたい範囲

ここで作る `CPU-3` は教材用の小さな実装です。森羅万象CPUと同じ独自48 bit命令形式を使いますが、対応するのは `add`、`sub`、`addi`、`subi`だけです。分岐、データメモリ、入出力、待ち時間はまだありません。

また、この命令形式はRISC-Vやx86ではありません。森羅万象プロジェクトが設計した独自ISAです。一般的なCPUの用語を学べますが、bit配置や命令番号はほかのISAへそのまま使えません。

## CPUを構成する5つの部分

今回の処理を順番に並べると、次のようになります。

```text
命令メモリ
    ↓ 48 bitの命令
デコーダ ──→ レジスタ番号・即値・演算の種類
    ↓
レジスタ ──→ ALU ──→ レジスタへ書き戻す

PC ──→ 今読む命令のアドレス
```

### 命令メモリ

命令を置く場所です。この教材では1命令が6 byteなので、アドレス0、6、12に3つの命令を置きます。

### PC

Program Counterの略です。現在読む命令の先頭アドレスを保持します。1命令を実行するたびに6を足します。

### デコーダ

48 bitを、命令の種類、レジスタ番号、即値などへ分けます。包み紙を開いて中身ごとに仕分ける部分だと考えてください。

### レジスタ

CPUの内部にある小さな記憶場所です。今回のレジスタは32本あり、1本につき32 bitを保存します。`r0`は常に0を読み出すゼロレジスタとします。

### ALU

前回作った計算回路です。デコーダが選んだ計算を行います。

## 48 bit命令の形式

今回使う形式は2種類です。表の左側が下位bitです。

### I形式

`addi`と`subi`に使います。

| bit | 幅 | 名前 | 意味 |
| --- | ---: | --- | --- |
| 4..0 | 5 | opcode | 大まかな命令の種類 |
| 7..5 | 3 | opcode_sub | その中の細かな種類 |
| 12..8 | 5 | rd | 結果の保存先 |
| 15..13 | 3 | rs1 | 入力レジスタ（r0～r7） |
| 47..16 | 32 | imm | 命令内に直接入れる数 |

I形式だけ `rs1` が3 bitなので、指定できるのは `r0`から`r7`です。この点はR形式と違います。

### R形式

`add`と`sub`に使います。

| bit | 幅 | 名前 | 意味 |
| --- | ---: | --- | --- |
| 4..0 | 5 | opcode | 大まかな命令の種類 |
| 7..5 | 3 | opcode_sub | その中の細かな種類 |
| 12..8 | 5 | rd | 結果の保存先 |
| 17..13 | 5 | rs1 | 1つ目の入力レジスタ |
| 22..18 | 5 | rs2 | 2つ目の入力レジスタ |
| 47..23 | 25 | reserved | この形式では使わない領域 |

## opcodeを決める

仕様書では、基本算術命令を次のように割り当てています。

| 命令 | opcode | opcode_sub | 計算 |
| --- | --- | --- | --- |
| add | 00001 | 001 | `r[rd] = r[rs1] + r[rs2]` |
| sub | 00001 | 010 | `r[rd] = r[rs1] - r[rs2]` |
| addi | 00010 | 001 | `r[rd] = r[rs1] + imm` |
| subi | 00010 | 010 | `r[rd] = r[rs1] - imm` |

`i`はimmediate、つまり即値を使う形式を表します。

## 命令をbyte列にする

最初の `addi r4 = r0, 3` は、48 bit全体では次の値になります。

```text
0x000000030422
```

命令メモリには1 byteずつ、下位byteから置きます。これをリトルエンディアンと呼びます。

```text
22 04 03 00 00 00
```

`bootrom.hex`全体は次の18 byteです。

```text
22 04 03 00 00 00   # addi r4 = r0, 3
22 05 05 00 00 00   # addi r5 = r0, 5
21 86 14 00 00 00   # add  r6 = r4, r5
```

実際のファイルではコメントを入れず、1行に1 byteを書いています。

## Fetch: 6 byteを1命令に戻す

```scala
val instruction = Cat(
  (0 until 6).reverse.map(i => instructionMemory.read(pc + i.U))
)
```

メモリから6 byteを読み、`Cat`で連結して48 bitへ戻します。ファイルには下位byteから置いたため、連結時は逆順です。

## Decode: 必要な場所を切り出す

```scala
val opcode    = instruction(4, 0)
val opcodeSub = instruction(7, 5)
val rd        = instruction(12, 8)
val rs1R      = instruction(17, 13)
val rs1I      = Cat(0.U(2.W), instruction(15, 13))
val rs2       = instruction(22, 18)
val immediate = instruction(47, 16)
```

`instruction(4, 0)`は、4 bit目から0 bit目までの5 bitを切り出します。I形式の `rs1` は3 bitなので、上位へ0を2つ足して5 bitのレジスタ番号にそろえています。

## Execute: ALUへの入力を選ぶ

R形式では2つのレジスタを使い、I形式では1つのレジスタと即値を使います。

```scala
alu.io.a := Mux(isImmediateForm, registers(rs1I), registers(rs1R))
alu.io.b := Mux(isImmediateForm, immediate, registers(rs2))
```

`Mux`は、条件に応じて2つの入力から片方を選ぶ回路です。

## Write Back: 結果を保存する

```scala
when(isSupported && rd =/= 0.U) {
  registers(rd) := alu.io.out
}
registers(0) := 0.U
```

対応している命令で、保存先が `r0`以外のときだけ結果を書きます。`r0`はゼロレジスタなので、書き込みを無効にして常に0を保ちます。

## クロックで状態が進む

`registers`と`pc`は `RegInit` で作ったレジスタです。組み合わせ回路だった加算器やALUと異なり、クロックの立ち上がりで新しい値を保存します。

| クロック後 | 実行した命令 | 状態 |
| ---: | --- | --- |
| 1 | `addi r4 = r0, 3` | r4 = 3、PC = 6 |
| 2 | `addi r5 = r0, 5` | r5 = 5、PC = 12 |
| 3 | `add r6 = r4, r5` | r6 = 8、PC = 18 |

## テストする

```console
cd CPU-3
sbt test
```

テストは各クロック後のPCを調べ、3クロック後に `r6`相当の出力が8になることを確認します。

これで、命令を順番に読み、解釈し、計算し、結果を記憶する最小限のCPUができました。

次は、条件分岐を追加して同じ命令を繰り返せるようにします。その後、データメモリ、UARTやSPIなどの入出力へ進みます。

# CPU自作の準備――まずは「回路を書く」環境を作ろう

> タグ: CPU自作 / Chisel / デジタル回路 / 初学者

こんにちは、森羅万象プロジェクトです。

このシリーズでは、CPUを一度に完成させるのではなく、小さな回路を動かしながら少しずつCPUへ育てます。対象は、プログラミングや情報工学を学び始めた高校生・大学生です。論理回路やScalaを知らなくても、必要になったところで説明します。

この記事のゴールは次の3つです。

1. このシリーズでいう「CPU自作」の意味を知る
2. ソフトウェアとハードウェア記述の違いを知る
3. サンプルプロジェクトのテストを実行する

## 何を自作するのか

CPUは、メモリから命令を読み、その命令に従って計算やデータの移動を行うデジタル回路です。このシリーズでは、森羅万象プロジェクトが決めた独自の命令形式を理解し、実行できる回路を作ります。

市販のPC用CPUと同じ性能や機能を目指すわけではありません。まずは次の流れを目で追える、小さなCPUを目指します。

```text
命令を読む → 命令を解釈する → 計算する → 結果を保存する
```

これはよく Fetch（フェッチ）、Decode（デコード）、Execute（実行）、Write Back（書き戻し）と呼ばれる流れです。後の記事で一つずつ作ります。

## はんだ付けをしなくても回路は作れる

「CPU自作」と聞くと、トランジスタやICを大量に配線する姿を想像するかもしれません。このシリーズでは、回路の構造をハードウェア記述言語で書き、最初はシミュレータ上で確かめます。

その後、設計データをFPGAへ書き込めば、実際の回路として動かせます。FPGAは、内部のデジタル回路の構成をあとから設定できるICです。

ここには3つの段階があります。

| 段階 | 何をするか |
| --- | --- |
| 回路記述 | 入力と出力、演算、レジスタなどの接続を書く |
| シミュレーション | 入力を与え、期待した出力になるかPC上で調べる |
| FPGA実装 | 記述した回路をFPGA内の回路資源へ割り当てる |

シミュレーションが通っただけでは、FPGA上で必ず動くとは限りません。クロック速度、ピン配置、タイミングなど、実機で初めて現れる条件があるからです。この違いは周辺回路を作る段階で扱います。

## Chiselとは

[Chisel](https://www.chisel-lang.org/)は、Scalaの文法を利用してデジタル回路を記述する言語です。正確にはScala上のハードウェア構築言語です。

たとえば、普通のプログラムにある

```scala
val answer = a + b
```

は、その行が実行されたときに足し算をします。一方、Chiselの

```scala
io.out := io.a + io.b
```

は、「入力 `a` と `b` を加算器へつなぎ、その出力を `out` へつなぐ」という回路を表します。見た目は似ていますが、作っているものが違います。

Chiselのコードは処理系によって回路表現へ変換され、最終的にはVerilog/SystemVerilogなどとしてシミュレーションやFPGAツールへ渡せます。「ScalaのプログラムがそのままCPUになる」という意味ではありません。

## 教材で固定するバージョン

この教材のサンプルは、プロジェクトの開発時期に合わせて次の組み合わせに固定しています。

- JDK 17
- Scala 2.13.12
- sbt 1.9.9
- Chisel 3.6.1
- chiseltest 0.6.1

Chiselは現在も開発が続いており、最新版ではライブラリ名やテスト環境が異なる場合があります。このシリーズでは、途中で環境差に悩まず回路へ集中するため、上の組み合わせを使います。新規プロジェクトで最新版を使う場合は、[Chisel公式の導入資料](https://www.chisel-lang.org/docs/installation)を確認してください。

## 必要なもの

次を用意します。

- JDK 17
- sbt
- コードエディタ
- このシリーズのサンプルコード

エディタはVisual Studio Codeを例にします。拡張機能は「Extension Pack for Java」と「Metals」があると便利ですが、テストの実行自体に必須ではありません。

WindowsでVerilatorを使った本格的なRTLシミュレーションを行う場合は、WSLなどのLinux環境が必要になることがあります。今回の最初の教材はchiseltestで動かすため、まずJDKとsbtから始められます。

## インストールを確認する

ターミナルで次を実行します。

```console
java -version
sbt --version
```

`java -version` に17系のバージョンが表示され、`sbt --version` がエラーにならなければ準備完了です。

## 最初のテストを動かす

サンプルコードの `CPU-1` ディレクトリへ移動し、テストを実行します。

```console
cd CPU-1
sbt test
```

初回はScalaやChiselなどを取得するため、時間がかかります。最後にテスト成功を示す表示が出れば環境は動いています。

エラーになった場合は、まず次を確認してください。

1. `java -version` と `sbt --version` が単独で動くか
2. ターミナルの現在地に `build.sbt` があるか
3. 初回のライブラリ取得中にネットワークが切れていないか
4. JDKとJava実行環境だけのJREを取り違えていないか

## この先の道のり

次回は、2つの8 bitの数を足す加算器を作ります。入力から出力がその場で決まる「組み合わせ回路」と、限られたbit幅で起きるオーバーフローを、短いコードとテストで確かめます。

# IOBusで周辺回路を選び、GPIOとタイマーを動かそう

> タグ: CPU自作 / IOBus / GPIO / タイマー / ready-valid / ポートI/O

UARTだけならCPUと直接つなげます。しかしSPI、GPIO、映像出力などが増えるたびに専用命令と配線を増やすと、CPU本体が複雑になります。

森羅万象CPUでは、`in` と `out` の要求をIOBusで振り分けます。2024年春から初夏にかけて、待ち合わせの修正、GPIO、クロックカウンタを追加しました。

## デバイスIDで行き先を選ぶ

CPUは命令からデバイスIDを取り出し、IOBusへ要求を送ります。IOBusはIDを見て対象の回路だけを選びます。

| ID | 主な用途 |
| ---: | --- |
| `0` | UART |
| `1` | SPIの送受信データ |
| `2` | SPIモード |
| `3` | SPIクロック分周 |
| `4` | GPIO出力 |
| `5` | GPIO入力 |
| `6` | 映像モード |
| `7` | パレット |

この表はISA v1期の割り当てです。カウンタ類など、より大きいIDを使うデバイスもあります。

```text
                 ┌─ UART
CPU ── IOBus ────┼─ SPI
                 ├─ GPIO
                 ├─ Video
                 └─ Counter
```

## 要求と完了を分ける

UARTやSPIは、要求した瞬間には処理が終わりません。CPUとデバイスの間では、少なくとも次を区別します。

- 何を読み書きするか
- 要求が有効か
- デバイスが要求を受け取れるか
- 読み出しデータが有効か

開発中には、`out` がデバイスの完了を待たずに終わる問題や、IOBusの `ready` が誤ったタイミングで立つ問題を修正しました。送信要求を出したことと、周辺回路が受理したことは同じではありません。

```text
要求成立 = valid && ready
```

CPUは成立するまでPCや対象レジスタを不用意に更新しません。IOBusは選択していないデバイスの `ready` を混ぜないようにします。

## GPIO出力

GPIO（General Purpose Input/Output）は、bitごとに外部ピンの0と1を扱う単純な周辺回路です。出力レジスタへ値を書き、そのbitをLEDや制御線へつなぎます。

```text
out device=4, value=0b00000001
                       │
                       └─ GPIO pin 0 = 1
```

GPIOはLEDの点灯だけでなく、SPIのChip Selectにも使いました。専用のCS制御をSPI回路へ固定せず、ソフトウェアから対象デバイスを選べます。

FPGAのピンへ出すときは、論理値だけでなく制約ファイルのピン番号、I/O電圧、LEDがactive highかactive lowかも確認します。

## GPIO入力

入力では、スイッチや外部信号の値をCPUから読みます。機械式スイッチは切り替え時に短時間0と1を往復するチャタリングがあるため、用途によっては一定時間同じ値が続いたことを確認します。

また、UART Rxと同様に、FPGAクロックと同期していない入力は同期回路を通します。シミュレーションで0か1に見えても、実機ではクロック境界付近で変化する可能性があります。

## クロック数とミリ秒を数える

CPUから一定時間待ちたい場面があります。SDカード初期化では、処理間隔やtimeoutをクロック数だけで書くより、時間として扱える方が分かりやすくなります。

森羅万象CPUの `ClkCounter` は64 bitのクロック数を数え、`ClockFrequency / 1000` を基にミリ秒を作ります。

```text
clock count: FPGAクロックごとに +1
millisecond: 1 msぶんのクロックごとに +1
```

64 bit値を32 bit CPUから読む場合、上位と下位を別々に読む途中でカウンタが進む問題があります。実装に応じて、読み出し時に値を固定する、上位を読み直して一致を確かめる、といった方法を検討します。

## pollingという待ち方

周辺回路の完了を繰り返し読む方法をpollingと呼びます。

```text
while (device is busy) {
    statusを読む
}
```

仕組みが単純なので、CPU自作の初期段階やブートローダーに向きます。ただし待っている間は別の処理をしにくくなります。後に割り込みを追加する場合も、まずpollingでデバイス単体の動作を確認しておくと切り分けやすくなります。

## テストで確認すること

- ID 0の要求がUARTだけへ届く
- ID 4への書き込みでGPIO出力だけが変わる
- 未定義IDで別デバイスが誤動作しない
- `ready` が対象デバイスの状態だけを反映する
- GPIO入力を読める
- 指定したクロック数でミリ秒カウンタが増える
- resetで各出力とカウンタが既定値へ戻る

## 今回の到達点

IOBusによって、CPU本体を大きく変えずに周辺回路を追加できるようになりました。GPIOは単純ですが、LED、入力スイッチ、SPIのCSなど多くの用途を支えます。タイマーは「何クロックか」を「何秒か」へつなぐ基準になります。

次は、クロックを共有してSDカードなどと通信するSPIを作ります。

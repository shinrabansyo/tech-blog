# UARTをつないで、CPUから文字を送ろう

> タグ: CPU自作 / UART / 非同期シリアル通信 / Tx / Rx / ready-valid

CPU内部の値を画面で見られないと、実機で止まった場所を調べるのは困難です。そこで最初の周辺回路としてUARTをつなぎます。UARTから1文字送れるだけでも、計算結果や進行状況をPCへ表示できます。

森羅万象CPUでは2024年1月から2月ごろに送信と受信を実装し、`out` と `in` 命令から利用できるようにしました。

## UARTはクロック線を共有しない

UARTは非同期シリアル通信です。送信側と受信側はクロック線を共有せず、あらかじめ通信速度を合わせて、1本の信号線上のbitを時間で区切ります。

ここでは、よく使われる「8 data bits、parityなし、1 stop bit」の1フレームを見ます。

```text
待機   start  data bits (LSB first)        stop  待機
 1  ...  0    d0 d1 d2 d3 d4 d5 d6 d7       1  ... 1
```

何も送っていないときは1です。0のstart bitを見つけると受信が始まり、8 bitのデータ、1のstop bitと続きます。

## baud rateから待つクロック数を求める

1秒あたりのbit数をbaud rateと呼びます。FPGAのクロック周波数が `ClockFrequency`、通信速度が `BaudRate` なら、1 bitあたりのおおよそのクロック数は次です。

```text
clocks per bit = ClockFrequency / BaudRate
```

たとえば12 MHzと115200 baudなら約104クロックです。割り切れない場合は少し誤差が出るため、送受信側の許容範囲に収まるか確かめます。森羅万象CPUの設定値は構成によって変えられるため、ボード側とPC側を同じ値へ合わせます。

## Txは1 bitずつ送る状態機械

送信回路Txは、1 byteを受け取ると次の順に動きます。

1. 待機中はTxを1にする
2. start bitとして0を出す
3. データのbit 0からbit 7まで順に出す
4. stop bitとして1を出す
5. 次のbyteを受け取れる状態へ戻る

各bitは決めたクロック数だけ保持します。現在の状態、何bit目か、bit内で何クロック待ったかをレジスタへ保存します。

送信中に次のbyteを渡されても、同じ回路ではすぐ処理できません。そこで「いま受け取れる」ことを示す `ready` と、「このデータを渡したい」ことを示す `valid` を使います。

```text
ready && valid のクロックでデータを受理
```

## Rxはbitの中央で読む

受信回路Rxは、start bitの立ち下がりを検出し、各bitの中央付近で信号を読みます。境界付近では送信側の信号が切り替わるため、中央の方が安定しているからです。

外部から来るRx信号はFPGA内部クロックと同期していません。そのまま状態機械へ入れず、複数段のフリップフロップを通して同期させます。これでメタステーブル状態の影響を後段へ伝えにくくします。

受信byteをCPUが読む前に次のbyteが来た場合は、古いデータを失う可能性があります。森羅万象CPUの実装ではoverrunも検出できるようにしています。

## CPUからはin/out命令で使う

CPUはUART内部の細かな状態を直接操作しません。IOBusを介して、デバイス番号と値を渡します。

```text
out: CPUから周辺回路へ値を送る
in : 周辺回路からCPUへ値を受け取る
```

UARTはデバイスID 0として扱われました。`out` で下位8 bitを送信し、`in` で受信した1 byteを読みます。CPU側はUARTが受理できるまで待ちます。

```text
CPU ── valid, device, data ──> IOBus ──> UART Tx
CPU <── ready, data ────────── IOBus <── UART Rx
```

## Helloを送る

文字は数値として送ります。ASCIIでは `H` は `0x48`、`e` は `0x65` です。

```text
0x48 0x65 0x6c 0x6c 0x6f 0x0a
 H    e    l    l    o   改行
```

各byteについて、UARTの `ready` を確認してから `out` を成立させます。送信中にPCが進んで次の文字を上書きしないようにします。

## 実機で確認する

PC側ではシリアル端末を開き、baud rate、data bits、parity、stop bitsをFPGA側へ合わせます。文字化けしたときは次を順に調べます。

- FPGAの実クロック周波数と設定値が一致しているか
- PC側のbaud rateが同じか
- TxとRxを逆に接続しているか
- GNDを共有しているか
- 電圧レベルがI/O規格に合うか
- 1 byteのbit順がLSB firstになっているか

## テストの分け方

Tx単体では、1 byteを送ったときのstart、各data bit、stopの長さを調べます。Rx単体では、テスト側から波形を入力して期待したbyteが出るかを調べます。最後にTxの出力をRxへ戻すloopbackで確認します。

CPU全体のテストでは、`out` が送信完了まで正しく待つこと、`in` が未受信データを読まないことを確認します。

## 今回の到達点

UARTによって、LEDだけでは分からなかった値をPCへ文字で送れるようになりました。これは入出力機能であると同時に、以後のSDカードやブート処理を調べるための重要なデバッグ手段です。

次は複数の周辺回路を選ぶIOBusと、GPIO、時間を測るカウンタを作ります。

### 用語について

UARTのUはUniversal、AはAsynchronousです。森羅万象CPUの古い仕様資料に「同期式」と読める記述があっても、記事では非同期シリアル通信として扱います。

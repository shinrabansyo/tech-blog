# アセンブラを作って、ラベルでプログラムを書こう

> タグ: CPU自作 / アセンブラ / 機械語 / ラベル / セクション

命令を1 byteずつ手で並べる方法は、数命令なら役立ちます。しかし分岐先が増えると、途中へ1命令足すだけですべてのアドレスを計算し直すことになります。

そこで、人が読めるアセンブリ言語を48 bitの機械語へ変換するアセンブラを作ります。森羅万象CPUでは2023年末に試作を始め、2024年にファイル入力、構文検査、ラベル、命令領域とデータ領域へ広げました。

## アセンブラの仕事

入力と出力の例を単純化すると、次のようになります。

```text
入力:
addi r4 = r0, 3
addi r5 = r0, 5
add  r6 = r4, r5

出力:
22 04 03 00 00 00
22 05 05 00 00 00
21 86 14 00 00 00
```

CPUが読むのは下側のbyte列です。アセンブラは上側の命令名、レジスタ、即値を解析し、ISAのbit位置へ詰めます。

## 4段階に分ける

森羅万象CPUのアセンブラは、処理を次のように分けて育てました。

1. **parse**：文字列を命令、レジスタ、数値、ラベルへ分解する
2. **check**：命令名やオペランドの数、値の範囲を検査する
3. **resolve**：ラベルを実際のアドレスへ置き換える
4. **convert**：命令形式に従って機械語を出力する

一度に全部を書くより、どの段階で間違ったかを特定しやすくなります。

## parse: 行を部品へ分ける

たとえば次の1行を考えます。

```text
addi r4 = r0, 10
```

少なくとも次の情報へ分けます。

| 種類 | 内容 |
| --- | --- |
| 命令 | `addi` |
| 出力 | `r4` |
| 入力 | `r0` |
| 即値 | `10` |

空白の数だけに依存すると、少し整形しただけで壊れます。区切り記号や数値の表記を決め、構文に合わない行には行番号付きでエラーを出すと使いやすくなります。

## check: CPUへ渡す前に間違いを止める

`r32` は5 bitのレジスタ番号へ入りません。大きすぎる即値も命令形式に収まりません。CPUへ渡してから原因を探すより、アセンブラで止める方が早く安全です。

チェック項目には次があります。

- 命令名がISAに存在するか
- 必要なオペランドがそろっているか
- レジスタ番号が範囲内か
- 即値が符号付きまたは符号なしの範囲内か
- 同じラベル名を二度定義していないか
- 参照先のラベルが存在するか

エラーメッセージには「何行目の、どの値が、どの範囲を外れたか」を含めます。

## resolve: ラベルをアドレスへ変える

森羅万象CPUのアセンブリでは、命令側のラベルに `@`、データ側のラベルに `$` を使う形が作られました。

```text
@loop
subi r4 = r4, 1
bne  r0, (r4, r0) -> loop
```

1命令は6 byteなので、命令を数えれば各ラベルのアドレスを求められます。一般的な方法は2回に分けることです。

1. 1回目でラベル名とアドレスの表を作る
2. 2回目でラベル参照を数値へ置き換える

これなら前方にあるラベルも参照できます。

## 命令とデータを分ける

プログラムには命令だけでなく、文字列や初期値も必要です。開発では区切り `===` を使ってセクションを分け、命令イメージとデータイメージを別々に出力できるようにしました。

```text
命令セクション
  addi ...
  ...
===
データセクション
  文字列や数値
```

データ用ディレクティブでは、1 byte、2 byte、4 byteの値や文字列などを表現します。出力先のエンディアンと配置アドレスをCPU側と一致させる必要があります。

## 機械語へ詰める

各命令形式に応じて、opcode、`rd`、`rs1`、`rs2`、即値を決められたbitへ置きます。その48 bit値を6個のbyteへ分け、森羅万象CPUが読むリトルエンディアンの順で出力します。

変換処理は、足し算で組み立てるより、各フィールドを必要な位置へシフトし、bit ORで結合すると意図を追いやすくなります。

```text
instruction =
    opcode
  | (opcode_sub << 5)
  | (rd         << 8)
  | ...
```

## アセンブラ自身をテストする

CPUのテストとは別に、アセンブラだけを検査します。

- 既知の1命令が期待する6 byteになる
- 負の即値が2の補数で入る
- 前方参照と後方参照のラベルを解決できる
- 命令を追加すると後続ラベルが6 byteずれる
- 不明な命令と範囲外の値を拒否する
- データの並びがCPUのリトルエンディアンと一致する

期待値を手計算した小さな例を残すと、命令仕様を変えたときの差分も見つけやすくなります。

## 今回の到達点

ラベルを使えるようになると、命令の追加や削除のたびにアドレスを数え直す必要がなくなります。データ領域も扱えるため、CPU上で長いプログラムを作る準備が整いました。

次はレジスタの役割をそろえ、関数を安全に呼び出すためのABIとスタックを扱います。

### 仕様について

ラベル記号やセクションの書式は森羅万象CPU向けツールのものです。ほかのCPUや一般的なアセンブラと同じとは限りません。

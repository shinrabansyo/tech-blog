# 関数を呼び出すために、ABIとスタックを決めよう

> タグ: CPU自作 / ABI / 関数呼び出し / スタック / レジスタ

分岐命令があれば別の場所へ移動できます。しかし関数として使うには、計算後に呼び出し元へ戻り、引数と戻り値を受け渡し、途中のレジスタを壊さない約束が必要です。

この約束をABI（Application Binary Interface）と呼びます。森羅万象CPUでは2024年8月から9月ごろにレジスタの役割、スタック、プロローグとエピローグを整えました。

## 関数呼び出しに必要なもの

関数 `add_two` を呼ぶ場面を考えます。

1. 引数を決められたレジスタへ置く
2. 戻り先を保存して関数へ分岐する
3. 関数が必要なレジスタを退避する
4. 計算結果を決められた場所へ置く
5. 退避した値を戻し、呼び出し元へ戻る

CPUは「これは引数」「これは戻り値」と判断しません。コンパイラ、アセンブリプログラム、ライブラリが同じ規則に従うことで関数として成立します。

## 森羅万象CPUのレジスタ規約

開発で定めた主な役割は次の通りです。

| レジスタ | 役割 |
| --- | --- |
| `r0` | 常に0 |
| `r1` | 戻り先アドレス |
| `r2` | スタックポインタ（SP） |
| `r3` | フレームポインタ（FP） |
| `r4`～`r7` | 一時的な作業用 |
| `r10`～`r19` | 引数と戻り値 |
| `r20`～`r29` | 呼び出された側が保存するレジスタ |

これは森羅万象CPU固有の規約です。RISC-VやArmなど、別のISAでは名前も役割も異なります。

## 戻り先を保存して分岐する

森羅万象CPUのv1分岐命令は、条件成立時に `PC + 6` を `rd` へ保存できます。

```text
beq r1, (r0, r0) -> add_two
```

`r0 == r0` は必ず真なので、`add_two` へ移動します。同時に次の命令のアドレスが `r1` へ入ります。関数の最後で `r1` が示す場所へ移れば、呼び出し元へ戻れます。

関数の中から別の関数を呼ぶと、`r1` は新しい戻り先で上書きされます。そのため、必要なら呼び出し前の `r1` をスタックへ退避します。戻るときは `jal r0, r1[0]` とし、`r1 + 0` をPCへ入れます。リンク先を `r0` にすることで、新しい戻り先の保存は捨てます。

## スタックは後から入れたものを先に出す

スタックは、関数ごとの一時データをメモリへ積む仕組みです。最後に積んだ値を最初に取り出します。

```text
高いアドレス
┌────────────┐
│ 呼び出し元の領域 │
├────────────┤
│ 保存した r1      │
│ 保存した r3      │
│ ローカル変数     │ ← sp付近
└────────────┘
低いアドレス
```

森羅万象CPUのABIでは、スタックは低いアドレス方向へ伸びます。領域を確保するときは `sp` を減らし、解放するときは同じ量だけ増やします。

## プロローグとエピローグ

関数の入口で作業領域を確保する処理をプロローグ、出口で元へ戻す処理をエピローグと呼びます。

```text
プロローグ:
  spを動かして領域を確保
  戻り先やfpをメモリへ保存
  fpを現在のフレームへ合わせる

エピローグ:
  保存した値をメモリから戻す
  spを呼び出し前へ戻す
  戻り先へ分岐
```

入口と出口は対になっています。確保したbyte数、保存した順番、復元した順番のどれかがずれると、少し後の関数呼び出しで壊れます。

## 呼び出す側と呼び出される側

すべての関数がすべてのレジスタを保存すると、命令数とメモリアクセスが増えます。そこで責任を分けます。

- 作業用レジスタは、呼び出す側が必要なら保存する
- `r20`～`r29` は、呼び出された側が値を変えるなら元の値を保存する
- 引数と戻り値は `r10`～`r19` を使う

関数単体では正しくても、規約を一つ破ると別の関数と組み合わせたときに失敗します。ABIはハードウェアだけでなく、アセンブラ、コンパイラ、ライブラリをつなぐ境界です。

## 小さな関数の流れ

2つの引数を足す関数なら、概念上は次のようになります。

```text
呼び出し元:
  r10 = 3
  r11 = 5
  r1に戻り先を保存して add_two へ分岐
  # 戻ったとき r10 = 8

add_two:
  r10 = r10 + r11
  jal r0, r1[0] で戻る
```

この関数は別の関数を呼ばず、保存が必要なレジスタも使わないため、スタックを省けます。複雑な関数だけが必要な領域を確保します。

## テストで再帰と入れ子を意識する

ABIのテストでは、単純な1回の呼び出しだけでなく次を確認します。

- 引数が関数へ渡り、戻り値が呼び出し元へ返る
- 関数から別の関数を呼んでも最初の戻り先を失わない
- 保存対象のレジスタが呼び出し前の値へ戻る
- ローカル変数が別のスタックフレームと重ならない
- 複数回呼び出してもSPが少しずつずれない

## 今回の到達点

ABIを決めたことで、人が書くアセンブリ、将来のコンパイラ、ライブラリが同じ方法で関数を呼べます。CPUの命令だけでは見えにくい「ソフトウェア同士の約束」が、長いプログラムを支えます。

次章では、UART、GPIO、SPIをつなぎ、CPUの外と通信します。

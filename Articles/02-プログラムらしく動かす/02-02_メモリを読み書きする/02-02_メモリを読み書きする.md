# loadとstoreで、データメモリを読み書きしよう

> タグ: CPU自作 / Chisel / メモリ / load / store / リトルエンディアン

レジスタは高速ですが、森羅万象CPUには32本しかありません。配列や文字列を扱うには、より広い保存場所であるデータメモリが必要です。

この記事では `lw` と `sw` を中心に、アドレス、byte幅、符号拡張、同期メモリの待ち時間を整理します。開発では2023年11月ごろからload/storeを加え、2024年にはFPGAのメモリへ合わせて同期化しました。

## 命令メモリとデータメモリ

最初のCPUでは、命令を置く場所だけがありました。データメモリを加えると役割を分けられます。

```text
命令メモリ ──命令──> CPU
                         │
CPU <────読み出しデータ── データメモリ
CPU ───書き込みデータ──> データメモリ
```

命令用とデータ用の経路を分ける構成は、ハーバードアーキテクチャと呼ばれます。後にSDカードから命令を読み込むときは、この分離が「CPUから命令メモリへどう書くか」という課題につながりました。

## アドレスはbyte単位

森羅万象CPUのデータは32 bit、つまり4 byteです。メモリのアドレスはbyte単位なので、32 bit値を順番に置くと開始位置は4ずつ進みます。

| アドレス | 置かれる範囲 |
| ---: | --- |
| 0 | 0～3 byte |
| 4 | 4～7 byte |
| 8 | 8～11 byte |

`lw` は4 byteを読み、`sw` は4 byteを書きます。byte単位の `lb`、`lbu`、`sb` や、2 byte単位の命令も同じメモリを一部だけ使います。

## ベースアドレスとオフセット

メモリアクセスでは、レジスタの値に命令内の即値を足して実効アドレスを作ります。

```text
address = r[rs1] + immediate
```

たとえば `r4 = 100` のとき、`4(r4)` に相当するアクセス先は104です。この形なら、配列の先頭をレジスタに入れ、即値で要素の位置を選べます。

## リトルエンディアン

32 bit値 `0x12345678` をアドレス100から置くとき、森羅万象CPUでは下位byteから並べます。

| アドレス | 値 |
| ---: | --- |
| 100 | `0x78` |
| 101 | `0x56` |
| 102 | `0x34` |
| 103 | `0x12` |

この並べ方をリトルエンディアンと呼びます。値の読み書きが間違って見えたときは、波形の32 bit値だけでなく、各byteが置かれた順番も確認します。

## 読み出しでは幅と符号を決める

1 byteの `0xff` を32 bitへ広げる場合を考えます。

- 符号付きの `lb`：`0xffffffff`、つまり -1
- 符号なしの `lbu`：`0x000000ff`、つまり255

符号付きloadでは、読み出した値の最上位bitを上側へ複製します。符号なしloadでは上側を0で埋めます。`lh` と `lhu` も同じ考え方です。

## storeでは書き込みマスクが必要

`sw` は4 byte全部を書きますが、`sb` は指定した1 byteだけを書きます。ほかのbyteを壊さないため、どのbyteを更新するか示す信号を用意します。

```text
address = 5 の sb
4 byteの並び: [address 4][5][6][7]
write mask :      0       1  0  0
```

このマスクは後のバスやキャッシュでも使う重要な情報です。

## 同期メモリはすぐ答えを返さない

Chiselの小さなサンプルでは、アドレスを与えた同じサイクルに値を使える書き方もできます。しかしFPGAのBlock RAMとして扱いやすい同期メモリでは、読み出し結果が次のクロック以降に出ます。

```text
cycle 1: CPUがアドレスを出す
cycle 2: メモリが読み出し値を返す
cycle 3: CPUが値をレジスタへ書く
```

CPUが返事を待たずに次の命令へ進むと、古い値を書いたり、別の要求と混ざったりします。そこで `ready` や `valid` のような信号を使い、要求と応答の成立を確認します。

## load/storeの状態遷移

単純なCPUなら、メモリ命令の間だけ状態を分ける方法があります。

1. アドレスと読み書きの種類を決める
2. メモリへ要求を出す
3. 応答が来るまでPCを進めない
4. loadならレジスタへ書き戻す
5. 次の命令へ進む

「待っている間に同じstoreを何度も発行する」といったバグを避けるため、要求を受理したか、応答を受け取ったかを別々に管理します。

## テストする組み合わせ

- `sw` で書いた32 bit値を `lw` で読める
- `sb` が隣のbyteを変えない
- `lb` と `lbu` で `0x80` 以上の結果が異なる
- アドレスに即値を正しく加算する
- メモリ応答を待つ間、PCと書き戻しが勝手に進まない
- 最初と最後の有効アドレスを扱える

シミュレーションが通っても、FPGAで推論されたメモリの種類や読み出しタイミングが違うことがあります。実機へ進む前に、合成レポートでBlock RAMの使用状況も確認します。
